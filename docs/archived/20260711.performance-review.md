## Historical Backtest Performance vs. Live Parity

A comparison of portfolio-level backtests against live execution shows high consistency across key performance vectors:

### 1. Multi-Timeframe Synchronization
- **Backtest**: Multi-timeframe candles are strictly synchronized on period closure (`current_ts >= ts + TF_SECONDS[t]`). This prevents look-ahead bias and achieves 100% indicator parity with live market feeds.
- **Live/Demo**: Real-time candles are updated on-tick. To prevent WebSocket noise or missing ticks, a periodic `Wick Parity Patcher` overlays official REST candles every minute, aligning historical backtests and live data precisely.

### 2. Multi-Asset Portfolio Capital Sharing
- **Backtest**: The `run_backtest_portfolio` system runs specified assets simultaneously along a shared chronological timeline, mimicking live margin limits and capital competition.
- **Live/Demo**: Trading loop respects `MAX_CONCURRENT_POSITIONS` globally across all running strategy threads, ensuring perfect matching of portfolio constraints.

### 3. Exit Trigger Order Synchronization
- **Backtest**: Supports split-target exits (TP1/TP2) and stop-loss levels.
- **Live/Demo**: Uses order presets for embedded stop-losses on entry. A position auditing loop inside `_sync_exchange_state` actively checks for open positions and automatically posts any missing TP1/TP2 plan orders on-exchange, solving the exchange's single-preset target limit.

### 4. Swing Target Cache Separation
- **Backtest/Live**: Incorporates starting and ending candle close prices into the cache fingerprint, preventing symbol cross-contamination and ensuring identical exit pricing between backtest and live modes.
