# Session Focus: System Audit & Architecture Alignment (2026-07-01)

## Key Decisions

1. **Strategy Families Architecture:**
    - Families will be defined by a hierarchical directory structure (e.g., `strategies/sweeps/range/`).
    - Running a family will load all strategies within that folder into a single `Engine` instance.
    - These strategies will share a common capital pool (`INITIAL_EQUITY`).
    - Position Contention: Different strategies within the same family ARE allowed to open opposing positions on the same asset (hedging).

2. **Compounding Math:**
    - Formally adding `REINVESTMENT_PERCENTAGE = 100` to the risk engine.
    - Results will now include a chronological equity curve to track trade-by-trade compounding toward the 100M "north-star."

3. **Historical Data Management:**
    - Moving from a heuristic "90% coverage" check to a strict range-based validation for DB candles.
    - Implementing a standalone `tools/downloader.py` that prioritizes candles over 4 years for all timeframes, with ticks as a secondary "bonus."

4. **Reporting & Observability:**
    - Full technical module metrics (40+ features) will be written to a shadow log at `docs/temp/[timestamp].metrics-log.txt` for every entry.
    - Statistics will be refactored to report per-strategy performance in addition to per-asset performance.

5. **Risk Engine Hardening:**
    - The hardcoded 5 USDT minimum notional is identified as a primary blocker for small-equity runs (15 USDT).
    - This will be replaced with a dynamic, exchange-sourced minimum to allow the bot to take trades even when risk-sized position values are low.

## Audit Findings Summary

- **Blocker:** The $5.00 minimum trade floor effectively prevents the bot from trading on a 15 USDT account when combined with 6.67% risk and wide stops.
- **Critical Risk:** "Hard Gates" in the predictive model are too restrictive, causing many high-probability setups to be rejected.
- **Operational Risk:** Lack of absolute pathing for `market_data.db` may be causing accidental database fragmentation/re-downloads during updates.

## Next Steps (Proposed)

1. Implement `tools/downloader.py` for 4-year historical retrieval.
2. Refactor `Engine` to support multi-strategy "Family" runs in a single process.
3. Update `Simulator` with dynamic minimum notional logic.
4. Implement the "Shadow Log" for full feature transparency.
