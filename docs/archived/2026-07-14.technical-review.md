# Technical Audit Report — 2026-07-14

This technical audit report provides a layer-by-layer review of the entire cryptocurrency futures trading system. It includes severity levels and clear action items for each finding.

---

## Resolved Priority Fixes

### **Issue A — KeyError: 'ts' (CRITICAL - RESOLVED)**
- **File**: `ta/patterns/sessions.py`
- **Functions**: `identify_core_range` and `identify_overnight_range`
- **Modes Affected**: All (Paper, Demo, Live) backtesting and execution running sweeps strategies.
- **Description**: Both the overnight sweep strategy (`killzone_sweep_overnight.1.mustafa.py` line 245) and the standard sweep strategy (`killzone_sweep.1.mustafa.py` line 254) manage dynamic queues of session range anchors. When a sweep occurs, they attempt to filter this queue using `r['ts'] != swept_range['ts']`. However, the helper functions `identify_core_range` and `identify_overnight_range` in `ta/patterns/sessions.py` created and returned range dictionaries that completely lacked the `'ts'` key, causing a fatal crash (`KeyError: 'ts'`) during backtests.
- **Root Cause**: The range construction paths in `ta/patterns/sessions.py` omitted the `'ts'` key when building range dictionaries.
- **Fix Applied**: Added `'ts': first_c['ts'] if first_c else None` (the starting timestamp of the continuous session block) to both range dictionaries inside `ta/patterns/sessions.py`.

### **Issue B — Unclosed aiohttp Client Session (HIGH - RESOLVED)**
- **File**: `backtest.py`
- **Function**: `main`
- **Modes Affected**: Backtest mode.
- **Description**: When a crash occurred (such as the `KeyError: 'ts'` in Issue A), `backtest.py` exited abruptly, bypassing the `await client.close()` call. This left the `aiohttp` ClientSession unclosed during interpreter teardown, triggering `aiohttp` to raise a shutdown warning, which crashed because Python's logging module was already shutting down.
- **Root Cause**: Lack of a robust exception-aware resource teardown sequence.
- **Fix Applied**: Wrapped the entire body of `main()` in `backtest.py` in a `try...finally` block. This guarantees that `await client.close()`, `db.stop()`, and the restoration and closure of `stdout_tee` and `stderr_tee` are *always* executed, regardless of whether the run completes normally, crashes, or is interrupted via `Ctrl+C`.

## Layer-by-Layer Technical Review Findings & Resolutions

### **1. Configuration Layer**
#### **Finding 1.1: Disconnected Dead Parameter `TARGET_NET_ROE` (MEDIUM - RESOLVED)**
- **File**: `config.py` / `models.py`
- **Description**: `TARGET_NET_ROE` was defined in `config.py` but hardcoded to `0.20` in the `LearningModel` inside `models.py`.
- **Resolution**: Refactored `models.py` to fetch `getattr(cfg, "TARGET_NET_ROE", 0.20)` dynamically, connecting the parameter as intended.

---

### **2. Exchange and API Layer**
#### **Finding 2.1: Hardcoded Maker/Taker Fees (LOW)**
- **File**: `engine/exchanges/bitget.py`
- **Functions Affected**: `place_order`, `get_trading_equity`
- **Description**: Standard maker and taker fees are referenced globally in some files but are hardcoded or assume static 0.02% / 0.06% fees.
- **Severity**: Low
- **Recommendation**: Ensure fee rates are always retrieved from `config.MAKER_FEE` and `config.TAKER_FEE` or queried from the Bitget API specs.

---

### **3. Data Layer**
#### **Finding 3.1: Sequential Historical Download Overhead (MEDIUM)**
- **File**: `simulator.py` (DataAcquisitionManager)
- **Functions Affected**: `fetch_all_data`
- **Description**: Large historical downloads run sequentially for up to 250 assets, creating significant startup delays and bottlenecking backtests.
- **Severity**: Medium
- **Recommendation**: Optimize `fetch_all_data` to perform concurrent chunked downloads with robust rate limiting.

---

### **4. Technical Analysis Modules (`ta/`)**
#### **Finding 4.1: Supertrend Direction Key Omission (HIGH - RESOLVED)**
- **File**: `ta/features.py`
- **Description**: `extract_features` calculated `supertrend_dir` but failed to inject `"supertrend_dir"` and `"supertrend"` into the returned features dictionary, causing the ScoringEngine Supertrend score evaluation to stay stuck at `0.0`.
- **Resolution**: Refactored `ta/features.py` to inject `"supertrend_dir": supertrend_dir` and `"supertrend": float(supertrend_dir) * 100.0` into the returned `features` dictionary, unlocking correct Supertrend scoring.

#### **Finding 4.2: Lack of Error Handling on Zero-Spread or Illiquid Books (LOW)**
- **File**: `ta/scoring.py`
- **Functions Affected**: `evaluate`
- **Description**: Linear mapping and spread evaluation can result in division-by-zero or default-to-zero when bid-ask books are thin or zero-spread.
- **Severity**: Low
- **Recommendation**: Add defensive checks ensuring `mid > 0.0` and `max_spread_pct > 0.0`.

---

### **5. Strategy Layer (`strategies/sweeps/`)**
#### **Finding 5.1: High Duplication of Quantity and Precision Rules (MEDIUM - RESOLVED)**
- **File**: `killzone_sweep.1.mustafa.py`, `killzone_sweep_overnight.1.mustafa.py`, `range_sweep_ATR.1.mustafa.py`
- **Description**: The math for resolving contract specification precision (`pricePlace` and `quantityPlace`), calculating minimum trade limits (`minTradeUSDT`), and performing decimal rounding was duplicated across strategy files.
- **Resolution**: Extracted and centralized rounding and precision logic into `format_order_quantity` and `get_price_precision` inside `tools/trading_utils.py`, refactoring all three strategies to import and use these helpers.

---

### **6. Engine Layer**
#### **Finding 6.1: Empty Status Variant IDs in `compare.py` (LOW)**
- **File**: `compare.py`
- **Functions Affected**: Main report builder / print loop
- **Description**: When running strategy comparisons without explicit parameter overrides, the variant ID is not populated, leading to empty status columns in the output table.
- **Severity**: Low
- **Recommendation**: Fallback to using the strategy file name as the variant ID.

---

### **7. Scoring and Filtering Layer**
#### **Finding 7.1: Non-Directional Penalty Dilution (MEDIUM - RESOLVED)**
- **File**: `ta/scoring.py`
- **Description**: Non-directional quality penalty factors (spread, ATR, volume, confidence) were included in the standard `total_weight` denominator even when they were perfect (`0.0`), diluting the directional indicators' final average score.
- **Resolution**: Redesigned `ScoringEngine.evaluate` to separate directional indicators from quality penalties. The directional score is calculated cleanly over directional weights only, and then the quality penalties are applied as direct additive/subtractive scores to the average, fully resolving indicator dilution.

---

### **8. Reporting and Logging Layer**

- **Severity**: Low

- **Severity**: Low
