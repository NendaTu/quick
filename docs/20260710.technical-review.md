# Technical Audit Report - 2026-07-10

## Priority Issues & Resolutions

### Issue 1 — P&L Discrepancy: Application Reports Profit, Exchange Shows Loss (CRITICAL)
- **Status**: **RESOLVED**
- **File**: `engine/core.py`, `bitget_client.py`, `engine/exchanges/bitget.py`
- **Root Cause**: The engine was calculating P&L on exited positions using the current ticker price (`self.exchange.last_price`) at the moment of state reconciliation, entirely ignoring entry and exit transaction fees.
- **Applied Fix**:
  1. Implemented `/api/v2/mix/position/history-position` as `get_history_positions` to query the exact closed position details directly from Bitget.
  2. Implemented `/api/v2/mix/order/fills` as `get_fills` to find exact exit order fill prices and fees.
  3. Created a bulletproof fallback in `_sync_exchange_state()` that uses the signal's target SL/TP limits and incorporates Maker (0.0002) and Taker (0.0006) fees (`calculate_net_pnl`).
  4. Updated virtual balance tracker inside `_report_exit` so that virtual balances update dynamically on exit.

### Issue 2 — Signal-to-Trade Conversion Failure (HIGH SEVERITY)
- **Status**: **RESOLVED**
- **File**: `engine/exchanges/bitget.py`
- **Root Cause**: Successfully placed limit entry orders were never registered in `self.pending_orders`, bypassing the limit chase and timeout queue. The asset stayed permanently locked in `self.pending_entries`.
- **Applied Fix**: Updated `place_order()` in `BitgetExchange` to append limit orders to `self.pending_orders` with the actual exchange `orderId`.

### Issue 3 — Live Trade Frequency vs. Backtest Frequency Gap (HIGH SEVERITY)
- **Status**: **RESOLVED**
- **File**: `engine/exchanges/bitget.py`
- **Root Cause**: Stale, unfilled limit entry orders would block further signals on that asset indefinitely because they were never canceled or chased.
- **Applied Fix**: Freeing up `pending_entries` via `_process_orders()` timeout chase checks restores the trade frequency back to standard backtest levels.

### Issue A — Leverage and Isolated Margin Enforcement (HIGH SEVERITY)
- **Status**: **RESOLVED**
- **File**: `bitget_client.py`, `engine/exchanges/bitget.py`
- **Root Cause**: Lack of leverage and margin configuration calls prior to order entry forced the exchange to default to account-level settings (often 10x leverage).
- **Applied Fix**:
  1. Added `/api/v2/mix/account/set-leverage` and `/api/v2/mix/account/set-margin-mode` to `BitGetClient` and `BitgetExchange`.
  2. Enforced maximum available leverage and Isolated Margin state automatically inside `BitgetExchange.place_order` right before order submission.

### Issue B — Split-Target Exit Trigger Orders (HIGH SEVERITY)
- **Status**: **RESOLVED**
- **File**: `bitget_client.py`, `engine/exchanges/bitget.py`, `engine/core.py`
- **Root Cause**: Bitget order placement presets only allow a single TP and SL target. Multi-target exit strategies (like TP1 and TP2) were not being fully posted on the exchange, leaving the position without secondary targets and with partial stop losses.
- **Applied Fix**:
  1. Added `/api/v2/mix/order/place-tpsl-order` as `place_tpsl_order` and `/api/v2/mix/order/orders-plan-pending` as `get_open_tpsl_orders` to `BitGetClient` and `BitgetExchange`.
  2. Implemented an active position-audit trigger order synchronization loop inside `Engine._sync_exchange_state()`. Every position sync audit checks for missing TP1 trigger orders and posts them automatically on-exchange.

### Issue C — Backtest Look-Ahead Bias and Mode Dependency (HIGH SEVERITY)
- **Status**: **RESOLVED**
- **File**: `backtest.py`, `bitget_client.py`
- **Root Cause**:
  1. Over-optimistic backtest performance was driven by a major look-ahead bias bug in the multi-timeframe synchronization loop. Multi-timeframe candles (15m, 1H, 4H, etc.) were synchronized as soon as the start of their period was reached rather than at their actual closed/completed time, granting up to several hours of future visibility.
  2. `backtest.py` instantiated `Engine` using `config.MODE` from `.env`. If it was live/demo, it initiated real exchange connections and failed if private API keys were missing or if it couldn't connect to private WebSockets.
- **Applied Fix**:
  1. Updated historical candle pre-population and synchronization in `backtest.py` so that a candle of timeframe `t` is only added once `current_ts` has reached or passed `ts + TF_SECONDS[t]`, completely eliminating look-ahead bias.
  2. Forced `mode="paper"` on `Engine` inside `backtest.py`, ensuring it runs strictly in simulation mode under any `.env` setting.
  3. Modified `BitGetClient` to return basic headers and allow successful public endpoint calls (candles, contracts) without requiring any private keys or raising signatures errors.

### Issue D — Premature Liquidation Protection (HIGH SEVERITY)
- **Status**: **RESOLVED**
- **File**: `engine/exchanges/bitget.py`
- **Root Cause**: If the distance to the Stop Loss exceeds the liquidation threshold (determined by the applied leverage), the position will liquidate on-exchange in Isolated Margin before the SL is hit.
- **Applied Fix**: Implemented dynamic safe leverage capping inside `place_order()`. Sourced `max_safe_leverage = int(0.9 / (abs(price - sl_price) / price))` and applied `min(max_leverage, max_safe_leverage)` to ensure the Stop Loss is always reached safely before liquidation.

- **Signal Schema**: Strategies comply fully with the signal schema, outputting `side`, `entry_price`, `stop_price`, and `exit_price` (TP price) which are utilized correctly by the routing and fallback P&L logic.
