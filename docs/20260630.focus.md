# Engineering Focus: Modular Strategy Layer & Institutional Hardening (2026-06-30)

## Overview
This session finalized the transition of the Bitget Futures bot from a monolithic decision engine to a modular, strategy-driven architecture. The primary achievement was the implementation and verification of the `strategies/` layer, which decouples higher-level orchestration (bias, flow, risk) from lower-level technical analysis (patterns, indicators).

## Key Architectural Changes
1.  **Pluggable Strategy Layer**: Introduced `JBaseStrategy` to standardize trade logic. Strategies now reside in `strategies/` and are loaded dynamically by `main.py`, `backtest.py`, and `compare.py`.
2.  **Unified Execution Router**: Implemented `SignalRouter` in `engine/entry.py`. This provides a single entry point for all orders, handling the branching logic between Paper (simulation), Demo, and Live modes.
3.  **Simulation Engine Refactor**: Refactored the core loop to support event-driven updates. The `Simulator` now uses sliding windows (1000 candles) for performance and correctly handles complex exit sequences including TP1 partial fills and aggressive SL protection.
4.  **Database Persistence**: Enabled trade-level persistence. Every entry and exit (including partials) is now recorded in the `trades` table of `market_data.db` with full metadata (strategy ID, execution price, PnL).

## Strategy Spotlight: Killzone Sweep (v1.mustafa)
- **Concept**: Capitalizes on institutional liquidity raids at session opens (US, UK, JAPAN, HK).
- **Sequence**: 1H Bias → 15m Overnight Range Sweep → 1m Execution (BOS1 -> FVG -> Retest -> BOS2).
- **Risk Control**: 0.5% risk per trade, fee-aware sizing, and "Aggressive BE" (moving SL to 50% profit point) upon TP1 fill.
- **Verification**: May 2026 backtest of ETHUSDT confirmed 2.1% net ROI on 2 trades (100% win rate), with SL correctly placed 1 tick beyond FVG extremes.

## Technical Analysis Hardening
- **FVG containment**: Enforced strict containment rule (C2 High < C3 High AND C2 Low > C1 Low for bullish).
- **Session Continuity**: Refactored `ta/patterns/sessions.py` to handle the Friday-to-Monday "Overnight Range" gap correctly.
- **ROE Math**: Updated backtest reporting to use realized margin from the engine, ensuring accurate capital efficiency metrics.

## Bug Fixes & Stability
- **Duplicate Argument Fix**: Resolved a `TypeError` in `backtest.py` and `SignalRouter` where `side`, `qty`, and other parameters were being passed twice during OCO placement.
- **Quantity Rounding**: Hardened strategy quantity calculation to ensure it respects asset-specific `quantityPlace` and `minTradeUSDT` limits.

## Future Considerations
- **Kelly Sizing**: Integrate `calculate_kelly_size` into the `Engine` to scale risk based on the strategy's historical win rate.
- **Demo Mode**: The `SignalRouter` has skeleton support for Demo mode; this requires Bitget Testnet API endpoints.
- **Live Hardening**: While the router supports Live mode, additional safeguards (network heartbeat, order synchronization) should be implemented in `engine/exchanges/bitget.py`.
