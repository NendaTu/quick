# Technical Analysis Document (July 2026)

**Audit Date:** 2026-07-01
**Auditor:** Jules (Senior Software Architect)

## 1. Historical Data Persistence (Consideration a)

### Findings
- **Location:** `backtest.py`, `download_historical_data()` function (Lines 94-110).
- **Issue:** The logic currently uses a 90% coverage threshold to decide whether to skip a download: `if count >= expected * 0.9: skip`. This heuristic is unreliable. If a database has 4 years of sparse data, it may meet the 90% count requirement for a 1-month backtest window without actually containing the specific candles for that window.
- **Recommendation (Priority: High):** Replace the count-based check with a range-based check. Implement a `get_data_gaps(asset, tf, start, end)` helper in `Database` to identify specifically which sub-ranges need downloading.

## 2. Standalone Historical Data Downloader (Consideration b)

### Findings
- **Location:** N/A (New Module Required).
- **Architecture Readiness:** The current `BitGetClient` and `Database` classes are well-suited for a standalone tool.
- **Recommendation (Priority: Medium):**
    - Create `tools/downloader.py`.
    - Logic: Discover assets via top volume, iterate all timeframes, work backwards 4 years.
    - Enforce a global `asyncio.Semaphore(10)` across all tasks to respect rate limits.

## 3. Running Strategies as a Family (Consideration c)

### Findings
- **Location:** `main.py` (`load_strategy`), `backtest.py` (`find_strategy_file`).
- **Issue:** Current discovery logic assumes a single file or a flat `strategies/` directory.
- **Recommendation (Priority: Medium):**
    - Refactor `load_strategy` to support directory-based discovery (e.g., `strategies/sweeps/range/`).
    - If a directory is passed as the strategy name, load all `.py` files within that tree as a "Family".

## 4. Shared Capital Pool Across Multi-Strategy Runs (Consideration d)

### Findings
- **Location:** `engine/core.py`, `simulator.py`.
- **Issue:** `compare.py` uses multiprocessing, which naturally isolates memory and capital.
- **Recommendation (Priority: High):**
    - **Single Process Mode:** For "Family" runs, the `Engine` must be capable of holding a list of strategy instances and passing market data to all of them.
    - **Position Contention:** The `Engine` must allow strategies within the same family to open opposing positions on the same asset (as requested by the user), while respecting the shared `self.equity`.

## 5. Chronological Compounding Curve (Consideration e)

### Findings
- **Location:** `engine/core.py` (`_report_exit`).
- **Issue:** Equity is tracked, but not recorded as a historical series.
- **Recommendation (Priority: Low):**
    - Add an `equity_history` list to `Engine` to record `(timestamp, current_equity)` after every trade exit.
    - Export this series to the results output for chronological PnL/ROI visualization.

## 6. Per-Strategy Trade Breakdown (Consideration f)

### Findings
- **Location:** `engine/core.py` (`asset_stats`).
- **Issue:** Statistics are aggregated primarily by asset, not by strategy.
- **Recommendation (Priority: Medium):**
    - Expand `asset_stats` to `strategy_stats` in the `Engine`.
    - Every signal returned by a strategy must include its `strategy_id`.
    - The `_report_entry/exit` functions must use this ID to bucket trades for reporting.

## 7. Full Module Metrics Reported with Every Entry (Consideration g)

### Findings
- **Location:** `engine/core.py` (`_report_entry`), `simulator.py` (`get_features`).
- **Issue:** Feature extraction is comprehensive, but reporting is selective.
- **Recommendation (Priority: Medium):**
    - Implement a "Shadow Log" in `docs/temp/[timestamp].metrics-log.txt`.
    - Every trade entry will trigger a full dump of the `features` dictionary to this file.
    - Ensure `Database.save_signal` persists the full JSON data.

## 8. Dynamic Minimum Trade Amount (Consideration h)

### Findings
- **Location:** `simulator.py`, `place_trade_oco()` (Line 704).
- **Issue:** The code uses a hardcoded `5.0` fallback for `minTradeUSDT`.
- **Recommendation (Priority: High):**
    - Map `minIdmValue` or `minNotional` from the Bitget API response to the `contract_specs`.
    - Ensure the position sizing logic satisfies this dynamic floor per asset.
