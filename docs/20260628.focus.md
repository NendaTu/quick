
## Finalized Requirements & Design
- **Architecture:** Multiprocessing-based isolation. Each variant (including the root config baseline) runs in its own process.
- **Variants:**
    - Method 1: `python compare.py config` - compares root `config.py` with any files in `compare/configs/`.
    - Method 2: `python compare.py VAR1=VAL1 VAR1=VAL2` - compares root with specified overrides.
- **Data Sharing:** A `DataCoordinator` will handle the single WebSocket connection and initial warm-up, sharing data with variants to respect rate limits and ensure identical market conditions.
- **Logging:** Bypasses SQLite database. Each variant logs to `compare/logs/[variant_id].log`.
- **UI:** Minimal console output during run (periodic summaries). Final side-by-side comparison table on exit (CTRL+C).
- **Metrics:** Net PnL (highlighted), Win Rate, Profit Factor, Sharpe Ratio, Max Drawdown, and current summary metrics.

## Implementation Strategy
1. **Refactor Engine/Simulator (Minimal):** Ensure `Engine` and `Simulator` can be "injected" with a data source or monkey-patched easily in a subprocess.
2. **Create `compare.py`:** The main orchestrator.
3. **Implement `DataCoordinator`:** Handles the heavy lifting of data acquisition.
4. **Implement `VariantRunner`:** The entry point for each subprocess that patches the config and starts the engine.
5. **Report Aggregator:** Collects results and formats the final table.
