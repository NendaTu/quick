# Implementation Roadmap: Scalper System Hardening - 20260628

This roadmap translates the findings from the 20260628 Audit into prioritized, actionable tasks to prepare the system for high-frequency compounding.

## Phase 1: Core Reliability & Statistics (High Priority)

### Task 1: Fix Trade Counting Logic
- **Finding**: Multi-stage exits (BE+TP1+TP2) artificially double trade counts and win-rate.
- **Action**: Modify `engine.py:Engine._report_exit` to only increment `total_trades` when `is_partial` is `False`.
- **Status**: Pending

### Task 2: Harden Concurrency Limits
- **Finding**: `MAX_CONCURRENT_POSITIONS` ignores pending limit orders.
- **Action**: Update `engine.py:Engine._trading_loop` to check `(len(self.open_positions) + len(self.pending_entries)) < MAX_CONCURRENT_POSITIONS`.
- **Status**: Pending

### Task 3: Signal Collision Prevention
- **Finding**: Asset tradability is only checked at the start of the tick loop, allowing dual-direction bursts.
- **Action**: Move `_asset_is_tradable` check to immediately before the `place_trade_oco` call in `engine.py`.
- **Status**: Pending

## Phase 2: Simulator Fidelity & Financial Logic (Medium Priority)

### Task 4: Fee-Aware Margin Checks
- **Finding**: Simulator approves market orders without reserving required entry fees.
- **Action**: Update `simulator.py:Simulator.place_trade_oco` to include estimated fees in the `available_balance` check.
- **Status**: Pending

### Task 5: Limit-Chase Margin Re-verification
- **Finding**: Converting limit entries to market (timeout) bypasses margin checks at new prices.
- **Action**: Add a `required_margin` check in `simulator.py:_process_orders` within the `entry_timeout` block.
- **Status**: Pending

## Phase 3: Performance Optimization (Medium Priority)

### Task 6: Feature Calculation Caching
- **Finding**: O(N) recalculation of all patterns on every tick is a major bottleneck.
- **Action**: Implement a `_feature_cache` in `simulator.py`. Patterns (FVG, OB, etc.) should only be recalculated when a new candle is detected for the symbol.
- **Status**: Pending

### Task 7: Shared BTC Confluence
- **Finding**: BTC move is recalculated for every asset request.
- **Action**: Calculate BTC confluence once at the start of `Engine._trading_loop` and pass it to feature requests.
- **Status**: Pending

## Phase 4: Technical Analysis Hardening (Low Priority)

### Task 8: Candle-Close Break Confirmation
- **Finding**: BOS/MSS signals based on unclosed candles lead to high false-break rates.
- **Action**: Add `CONFIRM_BREAK_ON_CLOSE` toggle to `ta/patterns/structure.py`.
- **Status**: Pending

### Task 9: FVG Tracking Optimization
- **Finding**: Logic scans post-gap history for inverted gaps every tick.
- **Action**: Modify `ta/patterns/fvg.py` to remove/ignore gaps once they reach the terminal `inverted` state.
- **Status**: Pending

### Task 10: IDM Killzone Precision
- **Finding**: IDM signals trigger on old sweeps if the bot enters a killzone window later.
- **Action**: Update `ta/patterns/idm.py` to compare sweep timestamp with killzone start time.
- **Status**: Pending

### Task 11: Standardize ROE Target Math
- **Finding**: Inconsistency between decimal ROE and percentage-based logging.
- **Action**: Enforce decimal values (0.05) for all target configs and update `LearningModel.predict` logging.
- **Status**: Pending
