# Technical Audit Report - 2026-07-08

## Overview
This report covers the technical integrity, architecture, and module integration of the Bitget USDT-M Futures trading system. The audit focused on core engines (`main`, `compare`, `backtest`), exchange connectivity, and risk management logic.

## Technical Findings

### 1. Exchange API & Connectivity
- **Dual-Client Architecture**: **[STABLE]** The implementation of separate `data_client` (Live) and `execution_client` (Mode-specific) successfully resolves "Error 40099" in Demo mode while ensuring high-quality market data.
- **Order Placement**: **[VERIFIED]** Bitget V2 `place-order` correctly utilizes `presetTakeProfitPrice` and `presetStopLossPrice`. Verified via Live mode test order (BTCUSDT).
- **Rate Limiting**: **[ROBUST]** `BitGetClient` implements 7 retries with jittered exponential backoff and incremental delays, which is essential for high-frequency operations.
- **State Synchronization**: **[IMPROVED]** `Engine._sync_exchange_state` now reconciles both positions and pending orders upon startup and via private WS events. This prevents "ghost positions" after a bot restart.

### 2. Config & Parameter Integrity
- **Orphaned Variables**: **[MINOR]** `RELAXED_ROE_TARGET` is defined in `config.py` but not referenced in the logic.
- **Missing Variables**: **[MEDIUM]** `SL_MOVE` and `TARGET_NET_ROE` are referenced in `models.py` via `getattr` defaults but are absent from `config.py`, making them non-configurable by the user.
- **Redundant Logic**: **[MINOR]** `MIN_CONFIDENCE` default (0.66) is hardcoded in both `config.py` and `models.py`.
- **Rigid Cooldowns**: **[MEDIUM]** `REENTRY_COOLDOWN` in `Engine` is a global 60s hardcode. While it scales with ATR, the baseline remains fixed, which may bottleneck compounding frequency for scalping strategies.

### 3. Execution & Simulation Fidelity
- **Minimum Notional Bottleneck**: **[CRITICAL]** Bitget enforces a 5 USDT minimum amount for USDT-M futures. On a 15 USDT starting account, this allows only 3 concurrent positions even at 100% utilization. Strategies with wide stops may fail to place orders because the calculated `qty` for 6.67% risk is below the 5 USDT floor.
- **Order Book Impact**: **[PRO]** `Simulator` correctly implements exponential slippage for orders exceeding visible book depth, providing a realistic simulation of "brutal" market fills.
- **Latency Simulation**: **[PRO]** Randomized log-normal latency (avg 35ms) is correctly applied to all fills in Paper mode.

### 4. Code Quality & Errors
- **Logging Scoping**: **[FIXED]** Several `sweeps` strategies were failing to load due to `logging` not being defined or incorrect `self.logger` calls. This has been resolved.
- **Strategy Discovery**: **[STABLE]** The recursive strategy loader in `main.py` and `backtest.py` is robust and correctly handles both single files and directory-based "Families".
- **Comparison Engine Naming**: **[BUG]** `compare.py` fails to properly name variants in the status table when only strategies are specified without parameter overrides, resulting in empty ID strings.

## Severity Summary

| Issue | Severity | Status | Recommendation |
| :--- | :--- | :--- | :--- |
| Minimum Notional Floor | **High** | Observed | Reduce `RISK_PER_TRADE` or use higher leverage to ensure `qty * price` always >= 5 USDT. |
| Missing Config Variables | **Medium** | Identified | Add `SL_MOVE` and `TARGET_NET_ROE` to `config.py`. |
| Rigid Re-entry Cooldown | **Medium** | Identified | Move `REENTRY_COOLDOWN` to strategy-specific parameters. |
| Orphaned Config | **Low** | Identified | Remove `RELAXED_ROE_TARGET`. |

## Recommendations
1.  **Dynamic Risk Adjustment**: Implement a check that ensures every calculated trade quantity meets the Bitget 5 USDT minimum notional before attempting placement.
2.  **Strategy-Level Parameters**: Migrate `REENTRY_COOLDOWN` and `EXIT_STRATEGY` into the strategy `params` dict to allow "Sniper" and "Scalper" modules to coexist with different cadences.
3.  **Config Cleanup**: Align `models.py` with `config.py` to ensure all "magic numbers" are user-accessible.
