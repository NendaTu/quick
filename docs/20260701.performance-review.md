# Performance Analysis Document (July 2026)

**Audit Date:** 2026-07-01
**Auditor:** Jules (Senior Software Architect)

## 1. Pipeline Efficiency & Trade Frequency

### Findings
- **Observed Behavior:** In the user's recent backtest logs (`docs/latest-user-review-log.txt`), several high-quality assets (ETH, SOL, XRP) produced **zero completed trades** over a 6-month period despite multiple signal triggers in the log stream.
- **Root Cause:**
    1. **Hard Gates:** The `LearningModel.predict` function implements strict "Hard Gates" for nearly all indicators (RSI, MACD, Trend, Volume Influx). If any single gate is failing, the trade is rejected.
    2. **Minimum Notional:** The system enforces a $5.00 USDT minimum trade value. At $15.00 starting equity and a 6.67% risk (approx. $1.00 risk), a trade with a wide Stop Loss (e.g., >20%) would result in a position size too small to meet the exchange minimum, causing silent rejection in the simulator.
- **Impact on Goal:** The "compounding north-star" requires high frequency. Current settings prioritize "perfection" over "participation," resulting in stagnant capital.
- **Recommendation:**
    - Implement a "soft-scoring" system where indicators contribute to a weighted confidence score rather than acting as binary kill-switches.
    - Reduce the hardcoded $5.00 floor to the actual exchange minimum (e.g., $1.00) to allow compounding to begin at lower equity levels.

## 2. Multi-Strategy Performance (Consideration c, d, f)

### Findings
- **Observed Behavior:** Current architecture runs strategies in isolation (multiprocessing). This makes it impossible to assess how a "Family" of strategies would perform when competing for the same capital.
- **Goal Impact:** To achieve 378 trades in 6 weeks, we likely need multiple strategies (Scalping, Range Sweeps, Trend Following) working in tandem.
- **Recommendation:**
    - Transition "Family" runs to a single-process `Engine` that manages a registry of active strategy instances.
    - **Position Contention:** Allow "Long" and "Short" signals on the same asset from different strategies to both execute (hedging). This increases frequency and provides a more realistic view of the "Family" PnL.

## 3. Chronological Compounding (Consideration e)

### Findings
- **Observed Behavior:** Results tables currently show "Final Equity" and "Total ROI." This masks the "Path to 100M."
- **Goal Impact:** We need to see if the system is actually compounding trade-by-trade or if it's suffering from "win-big-lose-big" volatility that would break the compounding curve.
- **Recommendation:**
    - Update the reporting layer to output a chronological "Equity Curve" table.
    - Add `REINVESTMENT_PERCENTAGE` (default 100%) to `config.py` to formally support the compounding math.

## 4. Signal Attribution (Consideration f)

### Findings
- **Observed Behavior:** In multi-strategy backtests, it is difficult to identify which specific strategy within a chain triggered a trade.
- **Recommendation:**
    - Every entry in the console and DB must be tagged with the `strategy_id` (e.g., `[MUSTAFA_OV]`).
    - The final summary table must break down PnL and Win Rate per strategy, in addition to the asset-level breakdown.

## 5. Metadata Visibility (Consideration g)

### Findings
- **Observed Behavior:** Signals are reported with a subset of features (RSI, MACD, VOL). Patterns like `BOS/MSS` or `FVG` distances are hidden unless they are the primary trigger.
- **Goal Impact:** Without seeing "the ones that got away" or the state of inactive modules, we cannot iterate on the strategy effectiveness.
- **Recommendation:**
    - implement the `metrics-log.txt` shadow log to provide a "Full State" snapshot for every entry.

## 6. Simulation Fidelity (Audit Requirement 3)

### Findings
- **Observed Behavior:** `Simulator._process_orders` simulates intra-candle price paths (O -> H/L -> C).
- **Efficiency Leak:** The simulator uses `random.lognormvariate` to simulate network latency even in backtests. While realistic for "Paper Mode," this slows down 4-year backtests significantly.
- **Recommendation:**
    - Ensure `latency_simulation = False` is strictly enforced during `backtest.py` runs to maximize iteration speed.
