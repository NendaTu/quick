# QA/TA Enhancement Plan: High-Frequency Compounding - 20260628

This document refactors the 20260628 Quantitative & Technical Analysis opportunities into a concrete implementation plan to achieve the 1 USDT -> 100M North Star.

## 1. Indicator Logic Refactoring (Priority: High)

### RSI "Momentum Rider" State
- **Opportunity**: `RSI_BUY_FLOOR` and `RSI_SHORT_CEILING` block high-momentum trades.
- **Action**:
  1. Modify `models.py:LearningModel.predict`.
  2. If `RESTRICT_RSI` is True and RSI is in extreme zones (< 15 or > 80), set `signal['is_momentum_rider'] = True`.
  3. Reduce `ATR_SL_MULT` by 50% for these trades to tighten stops.
  4. Outcome: Captures "moon" and "flush" moves with aggressive capital protection.
- **Status**: COMPLETED

### Supertrend Scoring
- **Opportunity**: `RESTRICT_SUPERTREND` is a lagging hard gate.
- **Action**:
  1. Set `RESTRICT_SUPERTREND = False` in `config.py`.
  2. In `models.py:LearningModel.predict`, add `score += 1.0 if supertrend_matches_direction else -1.0`.
  3. Outcome: Increases trade frequency by allowing counter-trend scalps while still prioritizing trend-aligned entries.
- **Status**: COMPLETED

## 2. Advanced Pattern Integration (Priority: High)

### POI Confluence Weighting
- **Opportunity**: `poi_confluence_score` is calculated but effectively ignored.
- **Action**:
  1. In `models.py:LearningModel.predict`, if `poi_active` is True, add `score += (poi_confluence_score / 20)`.
  2. Require `score > 2.0` for trades where `poi_active` is False.
  3. Outcome: Forces the bot to favor entries at institutional interest levels (OB/FVG/Liquidity).
- **Status**: COMPLETED

### BOS vs MSS Differentiation
- **Opportunity**: Trend continuation (BOS) is safer than reversal (MSS) but they are scored identically.
- **Action**:
  1. Modify `models.py:LearningModel.predict` to check `features.get('structure_signal')`.
  2. If `bullish_bos`, add +1.5 bonus. If `bullish_mss`, add +0.5 bonus.
  3. Outcome: Prioritizes safer, trend-following setups for compounding.
- **Status**: COMPLETED

## 3. High-Frequency Capabilities (Priority: Medium)

### HFT-Lite: Trade Delta
- **Opportunity**: Limit order book imbalance lacks "aggressive" market order context.
- **Action**:
  1. Create `ta/indicators/flow.py` with `compute_trade_delta(trades)`.
  2. Update `Simulator._ws_callback` to maintain a small window of market trade data.
  3. In `models.py`, add a hard gate requiring `trade_delta` to match `direction`.
  4. Outcome: Confirms signals with actual market-buying/selling pressure.
- **Status**: COMPLETED

### Volatility Regime Modeling
- **Opportunity**: Fixed RRR is inefficient across different market states.
- **Action**:
  1. In `ta/indicators/atr.py`, add `detect_vol_regime(atr_history)`.
  2. If regime is "Expansion", increase `TARGET_NET_ROE` and `ATR_SL_MULT`.
  3. If "Contraction", reduce both to scalp tight ranges.
  4. Outcome: Dynamically adapts the system's risk-reward profile to current noise levels.
- **Status**: COMPLETED

## 4. Institutional Session Scaling (Priority: Low)

### Session Multipliers
- **Opportunity**: All times of day are treated equal despite massive volatility variance.
- **Action**:
  1. In `engine.py:Engine._trading_loop`, check `features.get('killzone')`.
  2. If in `london` or `ny_am`, increase `RISK_PER_TRADE` by 1.5x.
  3. Outcome: Concentrates capital exposure during the most predictable, high-volume institutional windows.
- **Status**: COMPLETED

### Statistical Arbitrage Filter
- **Opportunity**: Bot may over-trade highly correlated assets, increasing systemic risk.
- **Action**:
  1. In `Simulator.warm_up`, perform a rolling 24h correlation matrix.
  2. If Asset A and Asset B are > 0.9 correlated, only allow a trade on the one with higher `poi_confluence_score`.
  3. Outcome: Reduces drawdown during market-wide flushes by diversifying exposure across unique movers.
- **Status**: COMPLETED
